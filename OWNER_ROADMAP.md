# Owner roadmap for Elliott

This roadmap is for turning tollahcoin (`$IRAN`) into a legitimate, usable project that people can verify and buy. It separates what Cursor can build from what Elliott, as owner, must decide or complete with legal, treasury, exchange, and community partners.

## North star

Make `$IRAN` easy to verify, hard to misrepresent, and simple to buy.

That means:

- A verified contract with clear token properties.
- Public tokenomics and owner controls.
- Reliable website, docs, and social links.
- Visible liquidity and a repeatable buy path.
- Listing-ready metadata for DEX aggregators, wallets, and exchanges.

## Phase 1: Legitimacy foundation

### Elliott owns

- Choose the final legal name, project name, ticker, and jurisdictional approach.
- Speak with a crypto-aware attorney before making public sale, utility, yield, or investment claims.
- Decide final tokenomics: total supply, allocation, tax, burn, minting, ownership, vesting, and liquidity policy.
- Decide whether the project needs a company, foundation, or informal community structure.

### Cursor can build

- Public website with canonical contract links and risk disclosures.
- Token documentation that explains supply, controls, and owner permissions in plain English.
- Token metadata package for wallets and token lists.
- GitHub-hosted project docs for transparency.

### Exit criteria

- One canonical contract address is published everywhere.
- The website shows the same contract, chain, buy path, and risk language.
- Token properties are documented before major marketing begins.

## Phase 2: Contract quality

### Recommended token properties

- Use a widely reviewed ERC-20 implementation such as OpenZeppelin.
- Avoid hidden mint functions, blacklist functions, transfer traps, or surprise taxes.
- If any taxes exist, publish exact rates and maximum limits.
- If ownership remains active, use a multisig wallet and publish signer policy.
- If ownership is renounced, explain what can and cannot be changed afterward.
- Verify source code on PolygonScan.
- Add automated tests for supply, transfers, permissions, taxes, and owner-only functions.

### Cursor can build

- A contract workspace with tests and deployment scripts if you want to manage the token from this repo.
- A plain-English technical disclosure page for holders.
- A release checklist before each contract or metadata change.

### Exit criteria

- PolygonScan source verification is complete.
- Contract tests pass.
- Owner privileges are documented.
- Holders can independently confirm the token behavior.

## Phase 3: Usability and buying

### DEX path

- Create or seed a liquidity pool on a reputable Polygon DEX.
- Publish the official swap link with the output token prefilled.
- Show liquidity pool address, pair, and basic slippage guidance.
- Track Dexscreener, GeckoTerminal, and other public chart pages once available.

### Wallet and token-list path

- Submit logo, name, symbol, decimals, chain, and contract to wallet/token-list registries.
- Keep SVG/PNG logo assets consistent across site, wallet lists, and socials.
- Publish official links for website, X, Telegram, Discord, GitHub, and PolygonScan.

### Exchange path

- Start with DEX liquidity and organic volume.
- Apply to CoinGecko and CoinMarketCap after public liquidity, charting, socials, and website are stable.
- Approach centralized exchanges only after the project has clean docs, legal posture, liquidity, community traction, and compliance materials.

### Cursor can build

- Buy guide and exchange-readiness pages.
- Token metadata files.
- Exchange application data room checklist.
- Site integrations for official chart, pool, and explorer links once they exist.

### Exit criteria

- Users can buy through a verified DEX route.
- Wallets and trackers display the correct token logo and metadata.
- Listing applications use consistent facts and links.

## Phase 4: Trust operations

### Publish publicly

- Tokenomics.
- Contract address.
- Liquidity status and lock details, if locked.
- Owner wallet or multisig address.
- Roadmap updates.
- Known risks.
- Official communication channels.

### Avoid

- Guaranteed return language.
- Fake volume.
- Paid bot engagement.
- Unverified exchange claims.
- Multiple competing contract addresses.
- Hidden ownership controls.

### Cursor can build

- Transparency dashboard or docs page.
- Changelog for roadmap progress.
- Holder FAQ and support flow.
- Static data room for exchange submissions.

## Phase 5: Growth after launch

Elliott handles marketing, but marketing should point to verifiable facts:

- Weekly creator prompts and meme campaigns.
- Holder education posts that link to the buy guide and contract.
- Spaces or livestreams with transparent progress updates.
- Contributor rewards for useful work, not spam.
- Public milestone posts when legitimate listings, locks, audits, or integrations are complete.

2. Add a contract disclosure page once the verified source and owner permissions are known.

Cursor can make the project technically clearer, more transparent, and more usable. Cursor cannot make legal, compliance, investment, or exchange-listing guarantees. Elliott should use legal counsel before public fundraising, presales, exchange outreach, or any claims about expected market performance.
